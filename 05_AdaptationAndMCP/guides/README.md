# 用自己的六轴机械臂开展仿真编排

[English](README_EN.md) · 项目仓库：**https://github.com/Learn-to-innovate-and-Surpass/SinoGermanRobot**

本项目希望从**少量种子动作出发，通过受约束的随机扰动产生多条同类任务候选，再进行批量仿真筛选和任务复核**，减少反复逐点示教，并逐步积累更有价值的数据。推进顺序是：减少重复编程 → 积累经过检查、可复用的数据 → 后续对接 VLA 训练与评估。欢迎贡献机器人资料、仿真适配、候选扩增方法、失败案例、序列约束和数据采集接口。

当前实现以 **AUBO-i5 六轴机器人**为基础，i5H CAD 用于外观参考，连接网页仿真、动作文件审核和独立执行界面。其他六轴机器人的接入需要开发者修改并验证代码；当前没有上传照片或 DH 表后一键完成适配的功能。本指南首先帮助你准备资料、在独立副本中完成仿真适配；它不表示已经完成通用机器人控制或 VLA 训练。

长期目标是让用户围绕任务和约束组织机械臂作业，通过复用数据与技能减少逐个变化重写固定程序的工作，为柔性生产提供基础。模型和具有工具调用能力的智能体可以作为可替换组件，辅助资料理解、几何建模、候选扩增、仿真检查与数据整理，逐步减少人工切换工具的负担，同时保留关键选择、验证结果和执行授权的可见性。系统不预设未来主导的算法路线；数据、接口和评价方法应便于后续替换模型与算法。更高自主性、更易上手及更低适配成本是发展目标，需由具体任务验证。

## 1. 先准备这些资料

不懂的项目填写“未知／待测”，并让 AI 解释需要什么证据。每项参数注明来源、型号、文档版本和页码；网页资料保留厂家原始链接。

| 资料 | 你需要提供的内容 |
| --- | --- |
| 机器人身份 | 厂商、完整型号、六个关节的顺序与类型；实物铭牌照片；控制器型号单独记录。 |
| 运动学 | DH 或 MDH 参数表及其坐标系图；明确标准/改进约定、变换相乘顺序、表格索引、角度/长度单位、关节零位偏置和正方向。仅有一张无约定的参数表还不够。 |
| 几何与照片 | 有授权的 STEP、URDF、STL 等资料；正面、侧面、顶部、工具和安装位置照片，标出已测尺寸及照片对应姿态。没有 CAD 时，可先做标注为近似的简化外形。 |
| 坐标与末端 | 基座、工作台、法兰、工具 TCP、相机各自的原点与轴向；变换的“从哪个坐标系到哪个坐标系”。未测 TCP、手眼变换、安装偏移保持待测。 |
| 限制与禁区 | 每轴角度和速度限制及厂家依据；工具/线缆包络；禁区的参考坐标系、最小/最大角点、单位、来源及测量状态。加速度缺少依据时不得冒充厂家上限。 |
| 任务与判据 | 任务文字、来源动作、起终条件、必须保持的姿态/关键点/夹爪事件及允许误差；说明判据来自工艺要求、实测还是暂定规则。 |

**照片用于理解布局和外观，不能替代毫米级测量或坐标标定。** DH/MDH 表与 CAD 外形也不自动证明控制器零位、关节符号和工具 TCP 一致。例如厂家会明确表格单位与符号，提交时应一并保留；可参考 [Universal Robots 官方 DH 资料的组织方式](https://www.universal-robots.com/articles/ur/application-installation/dh-parameters-for-calculations-of-kinematics-and-dynamics/)，其中数值不适用于其他型号。

## 2. 从一次小任务开始

1. 按仓库根目录说明启动现有网页，先熟悉第三个“动作编排与避障”界面。已有 Python 3.11 时，可在仓库根目录运行 `py -3.11 -B simulation/launcher.py start`。网页仅使用本机回环服务；此步骤不需要机器人 SDK。
2. 保留原 AUBO-i5 版本，新建你自己型号的工作副本或分支。将上述资料交给 AI，先得到参数对照、缺失项和修改清单，再实施适配。
3. 先验证零位、单轴正负变化及多个组合姿态。用独立的厂家运动学参考或已有可信位姿记录对照位置和方向；同时比较网页与 Python 计算。误差容限应有依据。尚无参考证据时，只记录内部一致性，不宣称实机标定通过。
4. 加入工作台和禁区。当前检查器使用杆件/工具胶囊与轴对齐包围盒近似；旋转障碍需要明确采用保守包围盒还是扩展算法。视觉外形与碰撞几何分别维护：隐藏墙体仍应参与碰撞。ROS 的 [官方 URDF 示例](https://github.com/ros/urdf_tutorial/blob/ros2/urdf/07-physics.urdf) 也分别定义 `visual` 和 `collision`；当前项目不会自动导入任意 URDF。
5. 从一个明确任务、少量已知动作开始复用和修改。检查单点、相邻过渡及循环回首，再核对任务判据。几何代理通过后仍可能偏离任务；不能通过放宽关节变化范围来掩盖任务失败。

建议后续扩展为“种子动作 → 受约束随机扰动/插值 → 多条同类候选 → 批量仿真筛选与回放 → 任务复核 → 数据采集”。先规定可变关节、扰动幅度和阶段；保持冻结关节、抓取/释放事件、TCP 位置与姿态容差、顺序及起终条件。逐条检查起点到首步、步间和循环回首，记录种子来源、随机种子及筛选结果。**这条完整批量扩增流程是发展方向；当前网页的候选搜索与修正不能等同于已完成批量数据生成，更不是学习式生成模型。** 数量增加之外，还应评估任务有效性、覆盖范围和重复程度。

## 3. 可以直接复制给 AI 的提示词

将方括号内容替换为自己的资料。首次可以只提供已有项目，保留其余“未知”。

```text
我希望基于 SinoGermanRobot，在独立副本/分支中适配自己的六轴机械臂。
本轮只做仿真和离线验证；保留原 AUBO-i5 版本，不连接或驱动物理设备。
目标顺序：减少重复逐点编程；积累可复用且可追溯的数据；以后对接 VLA。
具体目标：由少量种子动作产生多条同类任务候选，受约束地随机扰动/插值，
再批量仿真筛选和回放；请明确现有能力与仍需开发的批量扩增接口。

机器人与任务：[厂商/型号/关节顺序/关节类型/任务说明]
厂家原始资料：[URL、文档版本、页码、使用授权或来源]
DH/MDH：[参数表、约定、变换顺序、索引、单位、零位偏置、关节正方向]
照片/CAD：[资料路径或附件、拍摄方向、已测尺寸、照片时的关节姿态]
坐标：[基座/工作台/法兰/TCP/相机的定义与变换方向；未知项写待测]
限制：[每轴角度/速度/加速度及依据；线缆和工具包络；未测项目]
禁区：[名称、参考坐标系、min/max、单位、是否仅防撞、依据/待测状态]
任务保持：[关键点/TCP位置与姿态容差/夹爪事件/次序/起终条件及依据]
种子动作：[格式、单位、来源、可变关节、冻结关节、扰动范围；没有则写无]

请按以下顺序工作：
1. 核对资料冲突和缺失，先问最多三个最关键的问题，每个问题解释用途。
   不能从照片猜测关节参数、零位、速度上限或标定结果；待测项保持待测。
2. 列出当前 i5 专用代码与目标型号差异，给出逐文件修改计划。
   同时处理 Python/网页运动学、外形、碰撞包络、关节范围和模型版本，
   不通过整体缩放旧机器人或只改名称来表示适配完成。
3. 在独立副本实现仿真，保留旧版本测试；为新型号增加独立参考姿态对照。
   明确弧度/角度、米/毫米以及 WXYZ/其他姿态格式的转换边界。
4. 先用少量候选验证扩增规则，再扩展批量。检查起点、步间、循环过渡和任务保持，
   记录来源种子、随机种子、扰动参数、失败原因及修改量；保留必要冻结关节，
   不移动关键任务事件来换取碰撞通过。原始动作与修订版分开保存，
   保留未知元数据，不伪造审核或执行记录。
5. 输出已验证、仅仿真假设、待测三类结论及复现步骤。
   参数不全时可交付标注清楚的外观草模，但不能称为运动学/执行适配成功。
6. 保持 legacy real_motion_enabled=false、workspace_limits.validated=false。
   本轮不为新型号启用 ReviewedActionGate 真机路径，不自动启动、回零或运动。
```

## 4. 开发者需要检查哪些位置

以下为当前代码定位，**不是已经实现的通用模型插件接口**。所有路径以仓库根目录为基准。

| 位置 | 适配关注点 |
| --- | --- |
| `src/robot_model.py` | `load_scene()`、`pose_matrices()`、`controller_pose()`；六轴数量、关节轴/原点、控制器到外观的符号、基座配准、法兰方向。 |
| `simulation/static/editor-kinematics.mjs` | `controllerPoseData()` 中仍有六轴、i5 符号与 `-0.0235 m` 偏移，须与 Python 同步。 |
| `assets/robot_models/i5h_scene.json`、`tools/cad_conversion/` | 当前模型加载路径及 CAD 转换/构建流程；模型换名需一起修改加载器与版本绑定，URDF 文件本身不会替换此模型。 |
| `src/tool_geometry.py`、`src/workbench_frame.py` | 工具安装和碰撞胶囊；工作台到基座变换。现有工作台旋转不能直接套用。 |
| `simulation/action_editor_engine.py` | `CAPSULES`、`TABLE_OBSTACLES`、`LIMIT_DEG`、`options()`、`segment_check()`、`repair()`；现有统一 ±175° 等边界需逐项复核。 |
| `simulation/static/action-editor.js`、`action-editor.html`；`src/aubo_show_gui.py`、`real_show_gui.py` | 六轴控件、数值限制和型号文字；其余演示场景也含原任务姿态，不能直接套用。 |
| `src/action_review.py` | `model_revision()`、`validate_reviewed_action()`、`ReviewedActionGate`；绑定新模型/约束版本，旧审核不得继续授权。 |
| `tests/` | 保留 i5 基线；增加目标型号的独立运动学、前后端一致性、碰撞/序列/任务保持与离线阻断测试。 |

**实机适配是单独的后续开发阶段。** 当前执行路径面向 AUBO-i5，其他型号还需开发者检查 `src/real_robot_worker.py`、`src/real_action_core.py`、`src/robot_diagnostics.py`、`src/execution_speed.py` 和相关 `config/`，重新实现控制器接口、状态/停止语义、厂家速度依据、文件审核门控及起始姿态检查。修改 IP、替换 CAD 或选择一个型号名称都不等于完成适配。本指南不提供绕过门控的步骤。

## 5. 怎样积累有用的数据

建议保留“原始候选 → 修订候选 → 几何检查 → 任务复核 → 审核版本”的记录链，分别标注失败、仿真通过、任务复核通过、实机是否执行及其证据。当前 `execution_review` 绑定文件和场景，但不会自动证明任务语义、物理标定或训练质量；任务保持字段和检查应按具体任务补充。

后续采集器建议记录下列字段；这是**待实现的数据设计**，并非现有动作 JSON 已具备的输出：

| 内容 | 建议记录 |
| --- | --- |
| 视觉与语言 | 相机图像/视频帧引用、相机标识、任务文本及任务阶段。 |
| 状态与动作 | 实测关节/夹爪状态与下发动作分开；动作是绝对位置、增量还是其他量，以及单位、坐标系、关节顺序。 |
| 时间 | 帧与状态/动作各自时间戳、时钟域、同步方法、采样率、丢帧和延迟记录。 |
| 追溯与标签 | episode/step ID、种子动作ID/哈希、随机种子与扰动参数、机器人/工具/场景/标定/代码版本、修订和复核记录、成功/失败/中断、simulation/real 来源。 |

仿真阶段可进一步开发同步记录 RGB 画面、状态、动作、语言和时间的采集接口；现有网页回放和论文数据包不应直接标为可训练数据集。对接时可参考 [LeRobot 官方数据格式](https://huggingface.co/docs/lerobot/en/lerobot-dataset-v3) 对状态、动作、时间戳、视频和元数据的组织。需要实现字段转换、时间对齐、质量筛选与训练/评估划分，并防止同一来源轨迹的变体跨集合泄漏。不能仅给关节 JSON 加一句语言描述就声称获得完整 VLA 数据。

在 **https://github.com/Learn-to-innovate-and-Surpass/SinoGermanRobot** 提交 Issue/PR 时，请附型号、资料来源、适配范围、复现输入、版本和实际验证结果。优先贡献能复现的扩增与失败案例、任务保持判据及数据接口；照片、厂家资料与第三方模型按各自授权使用，自编代码以仓库根目录许可证的适用范围为准。减少示教和扩充有效数据是预期收益；已有小样本编排计时仅支持对应任务与完成标准，批量扩增效率和 VLA 训练收益需要另行验证。
